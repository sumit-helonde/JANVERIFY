# JANVERIFY — CODING RULES

## Permanent Rules

1. Never skip phases.
2. Build → Run → Test → Browser Verify → Backend Verify.
3. If failure:
   STOP → FIX → RETEST → VERIFY.
4. Never fake functionality.
5. Never use fake frontend application data after backend integration.
6. Never silently remove features.
7. Never silently change requirements.
8. Never change NRD-204 values.
9. Synthetic data must say SYNTHETIC HACKATHON DATA.
10. Never automatically declare fraud/corruption.
11. TRUSTMESH must remain explainable.
12. FRAUDSCOPE only identifies anomalies requiring review.
13. Evidence must remain source/date/method traceable.
14. Never expose secrets.
15. Never commit secrets from .env.
16. Every phase must actually be tested before being marked VERIFIED.
17. Update tasks.md after genuine phase completion.
18. Do not mark future work as completed.
19. Do not redesign the project without explicit instruction.
